# Pack dev tools

All tools run with the venv in `tools/.venv` from the repo root, for example
`tools/.venv/Scripts/python tools/smoke.py`. None of them are part of the pack (`/tools/` is in
`.packwizignore`). Generated state lives in `tools/.server` (headless test server) and `tools/.data`
(reports, recipe dumps); both are git-ignored. Recreate the venv with
`python -m venv tools/.venv` then `tools/.venv/Scripts/python -m pip install -r tools/requirements.txt`.

| Tool | What it does |
|---|---|
| `smoke.py` | Boots the pack on a headless NeoForge server with a fresh world, runs `/reload`, stops, and triages the logs. Also runs `smoke_checks.js` on the server (that GregTech's recipe-viewer mixins apply to the pinned JEI, that every quest item task and FTB Filter System filter in the book loads, and that Fowl Play's birds spawn by TFC's climate rule rather than their own). Exit code 1 on a crash, KubeJS error, or unknown error. |
| `startat_test.py` | Checks the `/startat` command on a fresh headless world: the start-point finder for a few real places, then the command itself as a non-op fake player (open water, first use, second use, bad input). Exit code 1 on any failure. |
| `logtriage.py` | Groups a log's warnings/errors, hides known-harmless ones (`known_issues.json`, each with a reason), and flags what's new since the last run. Default: the Prism client's `latest.log`; `--server` for the test server. |
| `pregen.py` | Pre-generates a fixed-seed area with Chunky (added to the test server for that run only) and reports chunks/second. `--place LAT,LON` centers it on a real-world spot in TFC: Real World. A fresh world is cached (`worldcache.py`): the same settings with an unchanged pack copy it in without a server run, and `--at HEAD` fetches the world made before your uncommitted change. `--no-cache` generates anyway. |
| `worldcache.py` | The cache behind `pregen.py` and `structure_mods/measure.py`, under `tools/.data/worlds/`. Keyed by the pack's generation inputs (mods, config, defaultconfigs and kubejs by git blob id, minus quests, client files, recipes, advancements and loot) and the run's settings, so a world is reused until something that could change it changes. A run is stored only when the server held exactly the pack. `list` shows what's cached and which entries match the working tree or HEAD, `key [--at REV]` prints the pack key (to name an ad-hoc probe's output by it), `prune`. 20 GB cap, least recently used out first. |
| `rocksample.py` | How far is igneous extrusive rock (andesite, basalt, dacite, rhyolite: what Create's andesite alloy needs) from a start, without generating chunks. A dev-only KubeJS script (`rocksample.js`) asks TFC's own rock generator on a fresh 20 m-per-block world, for each place's start: the rock, an estimate of the rock category, and the distance in blocks to the nearest extrusive surface rock and to the nearest reachable by digging ~100 blocks down, each also split into anywhere (land or seabed) and on dry land. `--places [NAME ...]` (default: 43 cities) or `--random N` (N land points worldwide, uniform by area, with the share that have extrusive rock within 500 to 25,000 blocks); `--rocks A,B,...` changes the target rocks (default the four extrusive ones, e.g. add `diorite`); `--validate world-rock-rome ...` checks the sampler against finished worlds. Report in `tools/.data/reports/rocksample-<timestamp>.json`. Uses the test server, so not while another tool does. |
| `worldgen_check.py` | Is the overworld's generation still frozen, so mods can be added or updated without a world wipe? Boots the test server on a fresh fixed-seed world at the pack's 20 m scale (about 2 minutes), fingerprints generation and compares it with the committed `worldgen_baseline.json`. Findings are **continuity-breaking** (seams in existing worlds: terrain, biomes, rock, carvers, veins, sea level, map; TFC and TFC: Real World changing is one by definition), **new-chunks-only** (a new feature, structure or spawn: each names the mod and how to strip it) or **info**; exit code 1 on the first two. Tier 0 reads the jars (worldgen data hashes, mixins into worldgen code; `--static` runs just this, in seconds), tier 1 the effective registries (generator, possible biomes, per-biome features, carvers and spawns, biome and structure modifiers and how many TFC biomes they reach, structures, tags, registry hashes, configs), tier 2 about 2,000 fixed points (TFC's own height, biome, rock and climate, no chunks generated). `--golden` adds tier 3: eight small areas generated with Chunky (added for the run only), compared per chunk (biomes, `tfc:chunk_data`, an underground rock, ore, air and fluid census) with checks that no foreign block, structure or entity appears; it is the only tier that sees code-level changes. Structures (`docs/lived-in.md`): their templates and the pack's own mod (`pack_world`, its classes) are hashed in tier 0, each accepted structure keeps a signature in tier 1 and the real-world sites' chunks are recorded, and the golden census leaves out chunks any structure reaches, on both sides, so an accepted structure doesn't read as a terrain change. Continuity-breaking changes are always refused. `--accept "<reason>"` folds new-chunks-only additions into the baseline with the mod, date and reason recorded; `--update --force-terrain "<reason>"` is the loud exception; plain `--update` makes the first baseline or takes info-only changes. Details in the script's docstring. Uses the test server, so not while another tool does. |
| `structures/build.py` | Builds the pack's structures (`docs/lived-in.md`) from `structures/catalogue.json`: structures, structure sets (TFC's climate placement), pools, processor lists, templates, loot tables and biome tags in `kubejs/data/pack/`, Easy NPC presets (`kubejs/data/pack/easy_npc/preset/`), and TFC: Real World waypoints for the ancient sites (`config/tfc_real_world/geography/pack/`). Templates are procedural (`structures/shapes.py`) or hand-built: drop a structure-block save built from the placeholder materials (granite, oak, alfisol, yellow sand) into `structures/templates/<structure>/<variant>.nbt` (sites: `templates/site/<site>/main.nbt`) and rebuild. Every template goes through a post-pass (empty TFC chests get the structure's loot table, a DATA structure block reading `npc:<id>` or `npc:<id>:spawner` becomes that Easy NPC, NPC owner, UUID and home are stripped) and a lint against the newest dump (blocks and items exist, loot within the era caps and off the deny-list, TFC biome ids). Lists the templates still waiting. The catalogue's `regions` and `villages` sections (the settlements, `structures/villages.py`, `docs/lived-in.md`, *Settlements*) go through the same checks: `--villages off|climate|region` picks what is written (the catalogue says `region`, the live form: `pack_world:region` placement and `pack_world:guarded_jigsaw`; `climate` is `tfc:climate` and a plain jigsaw, `off` only checks), `--simulate [N] [--layout]` places villages on flat ground with vanilla's jigsaw rules and prints pieces and NPCs per village. `--out DIR` stages a build for review. Edit the catalogue, not the generated files; it only rewrites the structure folders, never the cave files that share the namespace. |
| `structures/tfg_import.py`, `structures/villages.py` | The settlements. `tfg_import.py` converts TerraFirmaGreg's village templates (LGPL-3.0, pinned commit, `licenses/TerraFirmaGreg-structures.txt`) into `structures/templates/village/<culture>/<variant>/<piece>.nbt`: TFC 4 ids, the placeholder materials (granite, alfisol, yellow sand, and the culture's woods ranked `oak`, `spruce`, `birch`), Framed Blocks and Roads and Roofs where they are the best shape, vanilla carpets, NPC spots, jigsaw pools in the pack's namespace; deterministic, reports what it dropped or could not map in `templates/village/_import.json`. `tfg_import.py fetch` clones the pinned commit into `tools/.data/tfg-structures` (`--tfg DIR` uses another clone); run it only after editing its tables, the templates are committed. `villages.py` is the village schema `build.py` reads: multi-piece jigsaw villages, pools with fallbacks, per-piece processors, street markers, NPC pieces, regions, lint. |
| `structures/village_tune.py` | How many villages a set's climate, biome tag and guard let through. Reads the census `structures_test.py --villages --per-set 0 --acceptance` records (for every placement cell across a village's regions: whether the set's climate lets it through, TFC's climate there (temperature, rainfall, groundwater, forest), the biome and what a guard of radius 48 and 24 sees; no chunks are generated) and replays the catalogue's climate, biome groups and guard on it, or overrides (`--set norse --max-diff 14 --landforms +coast --biomes +tfc:grassy_dunes --water 0.2 --radius 24 --climate min_groundwater=15,max_temperature=36 --spacing 64`), printing per village the cells that survive each test, the reasons for refusals, the villages per million blocks squared of the regions and the mean distance between neighbours. A census made before the climate was recorded only holds the cells that passed it, so a wider climate needs a new census. Nothing is written: edit the catalogue to keep a change. |
| `structures_test.py` | Checks the structures on a fresh headless world with a dev-only KubeJS script (`structures_test.js`): every placeholder through the pack mod's own palette code for every TFC rock, wood, soil and sand; each structure generated at six real places (Rome, Stockholm, Lhasa, Manaus, Cairo, Kansas) and found where it generates naturally near them, read back for leaked placeholders, vanilla blocks, rough andesite-alloy rock, rock or wood that isn't the local one, and floating columns; every pack loot table rolled 200 times against the deny-list; a test NPC structure placed twice (separate NPCs, no owner, trades and dialog kept, spawners with their own UUIDs); the real-world sites' chunks; each structure's density. The villages (nested layout `structure/village/<culture>/<variant>/<piece>.nbt`) get their own section: region placement (21 reference places inside their set and outside the others, block coordinates equal to `worldview/geo.py`, the same cells as `tfc:climate` inside the region and none outside), the slope and water guard, codecs, wood ranks and Roads and Roofs mapping for TFC and ArborFirmaCraft woods, then per culture the nearest natural villages to its test places (why the others were refused: biome, water or slope) and every variant placed the way `/place` does with the guard off, read back per piece (pieces, Easy NPCs against NPC spots, placeholder leaks, vanilla blocks, rough alloy rock, rock and wood against the village's one choice (the rock and three woods at its start piece's centre), chests with loot tables, Framed Blocks camouflage, floating and buried ground, and for natural villages the tree leaves inside the pieces' boxes). The ruins the script places by hand next to the places (`/place` style) are skipped where they overlap a natural village. A `keep clear` stage checks that the keep-clear data is loaded, what it says about sample structures of each mod and that TFC's boulders carry the filter. The census `--acceptance` records every placement cell's climate too (see `village_tune.py`). `--villages` runs only those, `--no-villages` skips them, `--only-villages norse,steppe`, `--per-set N`. `--data DIR` and `--jar PATH` test a staged build, `--only` some structures. Report in `tools/.data/reports/structures-<timestamp>.json`. Uses the test server, so not while another tool does. |
| `loot/gen.py`, `loot/lint.py`, `loot/inventory.py` | The loot of the structure mods, in the pack's eras (`docs/lived-in.md`, *Loot rules*). `gen.py` writes from `loot/loot.json` (themes of weighted TFC items, archetypes of pools, per table an era and the size of the original) one era-capped loot table for every chest, barrel, pot, brushable and gift table the structure mods can put in a world (YUNG's Better Dungeons and Mineshafts, Moog's Voyager Structures, Missing Villages and Temples Reimagined, Towns and Towers, and the vanilla village, dungeon, mineshaft, stronghold, temple, shipwreck, ruin and archaeology tables they use) into `kubejs/data/<namespace>/loot_table/`, with the shared theme tables in `kubejs/data/pack_loot/`, empties GregTech's `gtceu:chests/extra/*` and writes `kubejs/data/neoforge/loot_modifiers/global_loot_modifiers.json` (`replace: true`, nothing kept), which switches off GregTech's nine global loot modifiers (steel, damascus steel, silver, chromium, gems ... in vanilla tables). `lint.py` boots the test server with a dev-only KubeJS script (`loot_test.js`), reads and rolls (300 times each) every chest, archaeology and gift table the pack knows (vanilla's, GregTech's, Lootr's and every mod's, nested tables and tags followed) and exits 1 on a deny-listed item or one above the table's era cap, a global loot modifier left active, a table a structure mod names that does not exist, a generated file that differs from `loot.json`, or an allow-listed table (Nether, trial chambers, mods that are not installed; the reasons are in the script) that a structure mod names after all. One summary line at the end. `inventory.py` lists every loot table the mods can place (template tags, worldgen JSON, mod classes) and the items the templates hold directly. `--results FILE` re-checks a saved run (`tools/.data/reports/loot-*.json`). Uses the test server, so not while another tool does. |
| `villagers_test.py` | Checks villager and wandering-trader trades (`docs/design.md`, *Villagers*). Without a server (`--static` stops here): `kubejs/config/villager_trades.json` against the newest recipe dump and the progression checker: every item exists; no result or price on the deny-list (`structures/catalogue.json`, `loot_caps`) or above the cap of its level (stone 6 for levels 1-2, copper 8 for level 3 and no bronze-family metal before level 4, bronze 13 for levels 4-5; wandering trader generic copper, rare bronze); no emeralds; stacks of 1-64; no trades that form a loop (an item bought in one trade and sold back for more in others). Then on a fresh headless world with a dev-only KubeJS script (`villagers_test.js`): what vanilla offered before the file replaced it (reported as shares: deny-listed, above the cap or unreachable, enchanted, maps, emeralds); that every price and result fits its item's stack; that villagers of every profession and level (30 of each) offer only the file's trades, two per level and all of them come up, and that wandering traders offer five generic and one rare of the file's; that a villager or wandering trader that joins the world holding emerald-for-iron offers gets the pack's, and one holding its own offers keeps them; that every structure template in the pack's jars that holds a villager, wandering trader or zombie villager, placed with its entities (the way a jigsaw piece does), ends up with the file's trades and whether its baked offers load at all; and the loot of the iron golem and the Hero of the Village gifts against the deny-list and the bronze cap. Report in `tools/.data/reports/villagers-<timestamp>.json`. Uses the test server, so not while another tool does. |
| `worldview/serve.py` | Browser viewer for a save: map (surface, height, TFC temperature/rainfall, lat/long grid), slices, Y distribution with host rock, chunk heatmaps. `--compare OTHER` adds a world B. Terrain far apart (after `/startat`) is split into areas, picked from a list; it opens on the player's. |

| `recipes/serve.py` | Recipe explorer: how anything is made or used, first route from the world, why something is unreachable, duplicate materials, progression rules (`recipes/progression.json`), and dump comparison. `--world` picks the world used as the starting point. |
| `quests/build.py` | Builds the FTB Quests book (`config/ftbquests/quests/`) from `quests/route.json`, then checks the route against the progression checker: every quest item exists and is reachable, and no quest comes before its prerequisites. Edit `route.json`, not the generated files. |
| `quests/pack_query.py` | Quest-writing lookups against the newest dump: an item's name, progression step and recipes (`item`), `search`, `tag`, `uses`. |
| `quests/port_tfg.py` | Ports TerraFirmaGreg's quests (LGPL-3.0): `fetch` pins its quest files at a commit, `extract` converts them to route.json's quest format with notes on what doesn't carry over, and `merge` applies the per-quest review (`quests/tfg_review/`, brief in `REVIEW.md` there) to `quests/route.json`. | `structure_mods/census.py` | Block census of the structure templates inside the structure mods' jars (Moog's, Towns and Towers, YUNG's, TFC Huts): per mod, how many blocks of each id, and the entities. No world needed; `--json` saves it for `skin_table.py --census`. |
| `structure_mods/skin_table.py` | Generates the structure skin's data (`kubejs/data/pack/pack_world/structure_skin/blocks.json` and `items.json`): every vanilla block of the newest dump mapped to its TFC counterpart (or `@keep`/`@air`), TFC's iron-age metal blocks to copper ones, vanilla and iron-age gear on armor stands and mobs to copper/bronze gear. How much to run. Each test-server run costs 5-7 minutes (1-2 to boot 79 mods, the rest generating), so match the checks to the stage:

- **While iterating:** the cheapest check that shows whether the change works. Offline first (`structures/build.py --strict` and `--simulate`, `villagers_test.py --static`, `worldgen_check.py --static`, `loot/gen.py`, the readers of an already generated world), then at most one targeted server run per attempt: `structures_test.py --only ...` or `--only-villages ... --per-set 1`, `pregen.py` at one place with `--radius 256` (about 1,000 chunks instead of the default's 16,600), `measure.py --places` one place. Not the whole loop below.
- **Once, before committing:** the full loop for the area, as listed below. Changes going into one commit share one full run; don't repeat it per edit.
- **Before/after comparisons:** never regenerate the "before". Check `worldcache.py list`; if it isn't there, generate it once before editing, with the settings you'll use after (same place, radius and seed). After the edit, `--at HEAD` with another `--world` name brings it back without a server run. Ad-hoc probe scripts: name their output by `worldcache.py key` and keep it in `tools/.data` so the next task can reuse it.

Typical loops (the full sets, for before a commit):

- After any mod or script change: `smoke.py`, then `recipes/dump.py` and check the explorer's Progression page, then `quests/build.py` (the route check uses the new dump).
- Before and after a KubeJS integration script: `recipes/dump.py --label before`, change, `recipes/dump.py --label after`, then *Compare dumps*.
- After a KubeJS, TFC: Real World or NeoForge update: `startat_test.py` too (the command leans on their internals).
- World generation changes: while iterating, `pregen.py --fresh --place LAT,LON --radius 256 --world world-after` at the one place that shows the change, against `pregen.py --place LAT,LON --radius 256 --world world-before --at HEAD`, compared with `worldview/serve.py tools/.server/world-after --compare tools/.server/world-before`. Before committing, the places that matter at the default radius the same way, and `worldgen_check.py --golden`.
- Structures (`docs/lived-in.md`): edit `structures/catalogue.json` or drop in a template, `structures/build.py`, `structures_test.py`, then `worldgen_check.py --golden` and `--accept "<reason>"` for the changed structure. The pack's mod (`mod/`): `./gradlew build` there with `JAVA_HOME` on JDK 22 (see `docs/lived-in.md`, *Status*), replace `mods/pack_world-*.jar` with the new jar from `mod/build/libs/`, `packwiz refresh`, then the same tests (any change to its code is a worldgen finding to accept).
- Villages (`docs/lived-in.md`, *Settlements*): edit the catalogue's `regions` or `villages` (spacing, regions, climate, guard, pools), `structures/build.py --strict`, `structures/build.py --simulate 100 --layout` for the layout, `structures_test.py --villages` (`--only-villages norse`), then `pregen.py --place LAT,LON` and `structure_mods/village_census.py --trees` on the world (`forest_census.py` for the other structures), `loot/lint.py`, and `worldgen_check.py --golden` with `--accept` for the changed set. After a TFC update: `structure_mods/keep_clear_overrides.py --check` (the boulders' copies). A change to a template: `tfg_import.py` (only for converted ones) or drop the hand-built file into `structures/templates/village/`.
- Structure mods (`docs/lived-in.md`, *Other mods' structures*): after adding, updating or removing one, `structure_mods/census.py --json`, `structure_mods/skin_table.py --check --census` (no gaps), `structure_mods/biome_tags.py` when the compat mod changed, then `structure_mods/measure.py` (`--mode before` and `after`) and `report.py`; a change to the pack's mod (`mod/`) goes through the same loop as the pack's own structures below.
- Loot of the structure mods: edit `loot/loot.json`, `loot/gen.py`, then `loot/lint.py` (about 3 minutes, test server). After adding or updating a structure mod run `loot/lint.py` too: it fails on every table the mod brings that is neither replaced in `loot.json` nor allow-listed, and `loot/inventory.py` shows where each one is used. After a recipe dump that moves items between steps, `loot/gen.py` again (the lint says the files are stale).
- After a change to `kubejs/config/villager_trades.json`, the villager scripts, KubeJS or NeoForge, or a mod that adds structures with villagers: `villagers_test.py` (`--static` after editing the file).
- After adding or updating any mod: `worldgen_check.py` (about 2 minutes); it must pass, or its findings say what to strip or accept. Before a release: `worldgen_check.py --golden` (about 3), the only run that sees code-level changes in generation. A reviewed new-chunks-only addition goes into the baseline with `--accept "<reason>"`, info-only differences with `--update`; commit `worldgen_baseline.json` with a message saying why.
